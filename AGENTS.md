# AGENTS.md

pnpm monorepo: a Next.js App Router app plus internal source packages. Layer and import rules are enforced by lint, not by convention.

## Commands

Run from the repo root. **`pnpm check` is the gate**: format check, lint (including layer boundaries), typecheck, locale parity, index freshness, unit tests, build of all apps. Run it before declaring work done. Remote CI runs no tests: it only builds and deploys. `pnpm verify` runs the same check in a clean Docker container, and the `pre-push` hook uses it on `main` and `develop`.

| Command                                                                  | Purpose                                                                       |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `pnpm install`                                                           | Install (run `nvm install` first; Node in `.nvmrc`, pnpm in `packageManager`) |
| `pnpm dev` / `pnpm dev:<app>`                                            | Run all apps / one app                                                        |
| `pnpm check`                                                             | The gate                                                                      |
| `pnpm lint` · `pnpm fmt` · `pnpm typecheck` · `pnpm test` · `pnpm build` | Single steps                                                                  |
| `pnpm index`                                                             | Regenerate the shared-code index below (the gate fails when it is stale)      |
| `pnpm e2e`                                                               | Playwright + axe (separate from the gate)                                     |
| `pnpm verify`                                                            | `pnpm check` in a clean Docker container (needs Docker)                       |
| `pnpm update-check`                                                      | Outdated deps, Node LTS, pnpm                                                 |

## Structure

```
apps/<app>/src/app/                  routes only (composition root)
apps/<app>/src/features/<f>/{domain,application,data,presentation}/
apps/<app>/src/shared/               this app's config and providers
apps/<app>/messages/{en,ko}.json
packages/ui/       @repo/ui      atoms, molecules, organisms, templates, styles/theme.css
packages/shared/   @repo/shared  domain (result, errors), data (http client, env), i18n
packages/config/   @repo/config  tsconfig, eslint, prettier, vitest presets
scripts/           init, add-app, update-check, verify, check-locales, agent-index
```

Before writing a component, hook, helper or use case, find it here and read its file; a UI package index in this file comes before `@repo/ui`. If nothing fits, say what you looked for, then add it to the right package with a one-sentence doc comment.

```text

@repo/shared/i18n/locales|locales: Supported locale codes. Locale: Union of the supported locale codes. defaultLocale: Locale used when none is requested. isLocale: Type guard that narrows a string to a supported `Locale`.

@repo/ui/lib/theme|Theme: Theme choice: `system` follows the OS preference. themeInitScript: Inline in `<head>` so the class is set before first paint (no flash). ## Rules
```

- **Layers** (inside one feature): `presentation -> application -> domain <- data`. Presentation may also use domain types. `domain` imports no framework (only `zod`).
- **Features are isolated**: a feature never imports another feature. Routes in `app/` import features and wire them together.
- **Packages**: `@repo/shared` imports no other workspace package; `@repo/ui` may import `@repo/shared`; packages never import apps; apps never import each other.
- Lint (`eslint-plugin-boundaries`, written generically for `apps/*` and `features/*`) fails the build on violations. Do not disable it; move the code instead.
- `@repo/*` packages are consumed as TypeScript source (`exports` + `workspace:*`). There is no build step and the scope is never renamed.
- **Adapters**: data adapters are prefixed `http-` (real API) or `mock-` (in-memory). Mock is the default; `NEXT_PUBLIC_ADAPTER=http` switches. The route (composition root) picks the adapter and passes it down.
- **Expected failures are values**: return `Result` from `@repo/shared/domain/result`; throw only for programmer errors.
- **Env** is read only through `@repo/shared/data/env`. Every value has a default, so the app runs with no env vars.
- **Versions live in the catalog** (`pnpm-workspace.yaml`). Packages use `"catalog:"`; never write a version in a workspace `package.json`.
- **Locale parity**: `messages/en.json` and `messages/ko.json` keep identical key sets (`pnpm check:locales`). All UI strings go through next-intl.
- **Reuse before writing**: find the component in the index blocks of this file first. If the product depends on a UI package that has its own index block here, that package comes first: use its components and variants, and let `@repo/ui` only compose them or add what the package lacks. Do not rebuild a package component because one detail differs: try its props, then write only the missing detail by hand and mark it `// TODO(library: <what is missing>)` (say what you tried), and report the gap to the package's maintainers. `pnpm lint` lists the open markers as warnings.
- **Replacing raw elements**: when a new atom replaces a raw element, add it to the replacement map in `packages/config/eslint/index.mjs`. A package that ships its own raw-element rule (merged into the product's ESLint config) owns the replacements for its components.
- **Config files** are `.ts` where the tool loads TypeScript without extra dependencies (`prettier.config.ts`, `next.config.ts`, `vitest.config.ts`, `playwright.config.ts`), otherwise `.mjs` (`eslint.config.mjs`, `postcss.config.mjs`). No `.prettierrc`.
- **Design tokens** live in one file, `packages/ui/src/styles/theme.css`. Apps scan `packages/ui` with `@source`.
- **Query keys** are `[domain, entity, params]`, e.g. `["billing", "invoice", { id }]`.
- File names are kebab-case and carry no role suffix (the folder is the role): `domain/user.ts`.
- Docs, code and comments are English.

## Starting a project

After cloning, run `scripts/init --name <name>` once. Add `--app <app>` to name the first app `apps/<app>` instead of `apps/web` (for example `admin`), and `--nested` when the template becomes a subfolder (`<product>/web/`) of a larger repo.
